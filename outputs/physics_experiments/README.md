## 为什么 `phys_full` / `phys_w*` 标记为无效

首版权重写成 `loss = data_loss + w * physics_loss`。但数据损失是 km 量级（~100），
物理项已归一化成 O(1)（~3.6），所以：

| w | 物理项实际占比 |
|---|---|
| 0.01 | 0.04% |
| 0.03 | 0.11% |
| 0.1 | **0.36%** |
| 0.3 | 1.07% |

**全部等于没加**，四组结果才会几乎完全相同（124.1~124.2，best_epoch 全为 11）。
修正为 `loss = data + w * data.detach() * physics` 后，才出现 `phys_r*` 那组干净的
U 形（最优 w=0.1）。详见技术报告 §4.11.4。

> 这四组的**日志保留**是为了留下证据链，**权重已删除**（不可用）。

| 保留 | 用途 |

| `phys_r0.1/checkpoints/best.pt` | 最优物理配置，作对照 |

复现其余配置只需重跑命令（约 5 分钟 / 组，GPU）：

```bash

# 硬约束（无物理损失）
python scripts/path/train.py --set device=cuda model.name=transformer_physics output.run_name=phys_hard
# 硬约束 + 物理损失
python scripts/path/train.py --set device=cuda model.name=transformer_physics \
       train.physics_weight=0.1 train.log_physics=true output.run_name=phys_r0.1
```

## 扰动集合

`perturb_ensemble.py` 的结果未落盘到本目录（输出到 stdout）。复现：

```bash
python scripts/evaluation/perturb_ensemble.py \
    --ckpt outputs/physics_experiments/phys_base/checkpoints/best.pt \
    --eps-km 200 --members 2 --limit 120
```

完整校准矩阵（`phys_base` 权重、120 样本、K=2、`--center control`）：

| 扰动方式 | eps=50 | eps=100 | eps=200 |
|---|---|---|---|
| 随机正交（`--steps 0`） | 40.2 / 0.498 | 79.6 / 0.798 | **165.5 / 0.958** ✓ |
| 增长优化（`--steps 10`） | 411.4 / 0.969 | 570.1 / 0.994 | 654.7 / 0.985 |

（数值为「平均离散度 km / 覆盖率@α=1.96」，名义 0.95）

关键结论：
1. **随机正交在 eps≈200 km 校准良好**（0.958 ≈ 0.95）
2. **增长优化会让离散度失控**（eps=50 就 411 km，随机版仅 40）——它找的是
   模型最敏感方向，属"最坏情形"而非"代表性误差"，不适合直接当集合成员
3. spread-skill 非单调（离散度来自输入敏感度，误差来自模型本身，两者不必相关）
4. 成员平均比控制预报差 +16~+137 km（故默认 `--center control`）
